# 能力梳理与简历素材（FThand 遥操 + OpenARM 协同 + VLA 数采）

> 基于实际完成的完整项目：数据手套 → 灵巧手遥操（FThand），双臂机器人（OpenARM）接入，端到端 VLA 动作数据采集。
> 分「科研向」和「工作导向」两版，可直接改写成简历 bullet。

---

## 一、项目一句话（放简历顶部/项目栏）

**开发了一套端到端的机器人遥操作 + 数据采集系统**：数据手套 → ROS2 节点链 → 灵巧手，并接入双臂机器人（OpenARM），实现"手 + 机械臂"协同遥操，输出 33 维动作轨迹数据用于 VLA（Vision-Language-Action）模型训练。全程在边缘设备（RK3588 / Jetson AGX Orin）上部署跑通。

---

## 二、科研向（研究实验室 / 算法组 / 实习，突出技术深度与方法论）

### 2.1 端到端 VLA 数据采集管线
- 搭建完整数据流：**数据手套（UDEGlove）→ UDP → ROS2 三节点（glove_driver / retargeter / hand_controller）→ 飞特舵机灵巧手**，并融合双臂机器人关节数据，产出**带时间戳的 33 维动作轨迹**（机械臂 16 + 灵巧手 16 + 时间戳），为 VLA 训练提供可对齐 observation/action 的数据格式。
- 设计了可插拔的中间映射层（retargeter）：规则映射可随时替换为 RL/学习策略，无需改动数据源与执行端。

### 2.2 跨平台移植与兼容性工程
- 将 ROS2 遥操系统从 Humble/Python3.8 移植到 **Jazzy/Python3.12**，系统排查并解决：Python 3.8 语法兼容（PEP 585 注解）、Python 3.12 的 `distutils` 移除、`ros2_control` API 弃用、C++ 依赖（CLI11）、Jazzy 参数类型严格校验等一整套版本差异问题。
- 通过 `ldd`/`readelf` 分析第三方二进制运行时依赖，识别 vendor 安装脚本中的冗余（实际只需 1 个共享库），将 30~40 分钟的部署压缩到 5 分钟，并自行编译缺失的 `libprotobuf.so.23`。

### 2.3 系统性能瓶颈定位与优化
- 用逐次计时（`get_motor_pos` ~8ms、`set_joint_pos` ~15ms）定位遥操卡顿根因：FeiTech 串口总线每次全读含 17 次逐电机电流读。
- 通过 I/O 优化（热路径跳过电流读取，`skip_current`）将控制循环 CPU 占用从 **85% 降至 45%**，控制频率从 60Hz 瓶颈下调至 30Hz 稳定运行，消除指令排队延迟。
- 从数据层面定位"抖动"根因：上位机空包 `{}` 与真实数据 1:1 交替导致状态清零，验证后通过来源隔离解决。

### 2.4 硬件/固件与数据链路诊断
- 掌握飞特（FeiTech）舵机串口协议、CAN 总线控制（OpenARM 双臂）、USB 串口枚举（CH343/CH340 → ttyACM），并设计 **udev 固定软链接** 解决拔插后设备号漂移问题。
- 系统性的故障排查方法论：串口 `lsof` 占用分析、UDP 数据流间隔统计（断档检测）、CPU 热负载分析、会话恢复陷阱等。

## 三、工作导向（企业 / 工程岗，突出交付、全栈、部署落地）

### 3.1 从零交付可落地的机器人遥操系统
- 独立完成一套**自包含遥操系统**在边缘设备（RK3588、Jetson AGX Orin）上的完整交付：环境搭建、依赖排查、代码移植、硬件接入、调参、一键部署。
- 配置 **systemd 开机自启**（服务端自启、控制链路手动启，平衡可用性与安全），环境变量管理（.bashrc/.profile），生产可用。

### 3.2 全栈技术栈（能独立干到交付）
- **ROS2**：节点/话题/参数/launch 全链路，亲手写并参数化 3 个 launch（遥操、录制、回放），新增 3 个采集/回放节点。
- **Python**：多进程/多线程、串口、socket/UDP、JSON/CSV 数据管道。
- **C++/CAN**：OpenARM 双臂 ros2_control 硬件接口、SocketCAN 电机控制。
- **部署**：systemd、udev、nginx（上位机 Web 客户端）、Git、scp 远程部署。

### 3.3 疑难问题排查与性能优化
- 多次定位"看似无解"的卡顿/抖动：Chromium 浏览器占用 400% CPU 拖垮整机、Windows 上位机空包干扰、USB 接收器掉线重枚举、会话恢复自动重开等——均有数据佐证（`ps`/`ss`/`dmesg`/`uptime`）与可复现的解法。
- **经典排障案例**：回放命令"到了"但执行机构不动——用分层验证（日志→串口→单关节→全关节→重启干净实例）逐层排除数据链路/硬件/总线，最终定位为长驻进程被并发访问污染。沉淀为可复用的**分层排查方法论**。

### 3.4 数据采集与后续拓展
- 打通 **VLA 数采流程**：录制（含手动停/定长）、CSV 落盘、回放闭环，数据格式与 OpenARM `vla_collection` 对齐，为后续真机 + 大模型训练打好基础。

## 四、可写进简历的量化点（bullet 模板）

- 将机器人遥操系统从 PC 移植到 **ARM 边缘设备（RK3588/Jetson）**，实现完全脱离上位机的自包含运行。
- 通过串口 I/O 优化，将遥操控制环路 CPU 占用 **降低 ~47%**，消除指令排队导致的延迟。
- 独立搭建 **ROS2 多节点 + launch 自动化** 遥操/数采架构，支持 **33 维动作轨迹**录制与回放。
- 完成 **Humble→Jazzy、Python 3.8→3.12** 全栈移植，解决十余类版本兼容问题。
- 部署 HandDriver Web 上位机至 ARM64，通过依赖分析将部署时间压缩 **80%+**。
