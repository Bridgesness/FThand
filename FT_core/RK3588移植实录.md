# FThand 移植到 RK3588 —— 全程实录

> 目标：把 FThand 遥操作（纯 Python 版 + ROS2 版）从 Windows/WSL2 移植到 **RK3588 板子**，跑通并尽量自包含（脱离电脑）。
> 本实录记录**实际执行过的每一步、遇到的问题和根因**，与 `ROS2改造方案.md`（设计）、`ROS2改造实操全步骤.md`（WSL 阶段实操）互补。
> 时间：2026-08-13

## 0. 目标环境与最终架构

### 板子信息

| 项      | 值                                              |
| ------ | ---------------------------------------------- |
| 板型     | LubanCat RK3588（8 核 ARM64）                     |
| 系统     | Ubuntu 20.04.6 LTS（focal）                      |
| ROS2   | **Foxy**（不是 WSL 的 Humble）                      |
| Python | **3.8.10**                                     |
| 登录     | `ubuntu@192.168.110.44`（密码见密码管理器，**sudo 免密**） |
| IP     | 192.168.110.44（wlan0，DHCP 动态，重启可能变）            |

### 硬件

| 设备                           | Linux 设备节点                      | 识别依据                                              |
| ---------------------------- | ------------------------------- | ------------------------------------------------- |
| 灵巧手（FeiTech 舵机）              | `/dev/ttyACM0`                  | CH343（`1a86:55d3`，`USB_Single_Serial`）            |
| 手套接收器（UDEXREAL Pro_Receiver） | `/dev/ttyACM1` + `/dev/ttyACM2` | CH340（`1a86:0001`，`UDEXREAL Pro_Receiver`，两个串口接口） |

### 最终自包含架构（Python 版已跑通）

```
数据手套 ─蓝牙→ 接收器(插板子) ─USB→ HDService(板子上跑 HandDriver Web)
                                      │ UDP 127.0.0.1:8000
                                      ▼
                        teleoperation.py(板子) → 机器左手
```

彻底脱离电脑；Web 配置界面在 `http://192.168.110.44:8088/`（用电脑浏览器打开即可）。

## 1. 分阶段操作记录

### Phase 1：代码兼容性排查（最重要的一步）

**问题**：代码在 WSL（Humble/Python3.10）下写，板子是 **Foxy/Python3.8**。
**扫描全包后唯一硬伤**：`orca_core/core.py` 三处 `-> tuple[bool, str]` 注解是 **Python 3.9+ 语法**，3.8 下 import 直接 `TypeError: 'type' object is not subscriptable`。
**修复**：改成裸 `-> tuple`（`connect`×2、`disconnect`）。Windows 源 + 板子副本都改了。

> 其余全包没有 3.9/3.10 语法（无 `X | None`、无 match、无 removeprefix）。

### Phase 2：源码来源统一（避免分叉）

- 发现 WSL 的 `~/FThand` 与桌面源 `C:\...\FThand\FThand` **已经分叉**（teleoperation.py、core.py、左右模型配置都不同）。
- 用户决定：**以桌面源为准**（参数今天下午刚调好：张紧/回零/标定）。
- 删除 WSL 旧副本 `~/FThand`，把桌面源 scp 到板子 `/home/ubuntu/FThand/`（结构保持 `~/FThand/FThand/FT_core`，节点靠这个路径解析）。

### Phase 3：纯 Python 硬件级跑通

1. 手插板子 → `ls /dev/ttyACM*` 发现 `/dev/ttyACM0`（CH343 在 Linux 是 **CDC ACM**，不是 ttyUSB！）。
2. `ubuntu` 不在 `dialout` 组 → 串口打不开 → `sudo usermod -aG dialout ubuntu`（或临时 `sg dialout -c "..."`）。
3. `python3 hand_neutral_test.py`（默认左手）→ 连上、读数、缓慢移中性位 ✅。
   - 唯一未标定：**pinky_abd（motor 12）**，`_filter_calibrated` 会自动跳过，属已知正常。
   - 脚本报的"读位置失败"是**误导**：不是通信问题，是脚本对未标定关节读到 `None` 后 `f"{v:8.2f}"` 格式化崩溃，纯脚本 bug。

### Phase 4：手套数据链路（发现"上位机"角色）

- 项目里的 `UDEGloveSDK`/`monitor_glove_udp.py` **只是 UDP 接收端**，不读接收器串口。真正把接收器转成 UDP JSON 的是手套厂的**上位机（HandDriver）**。
- 先测"接收器插 Windows + Windows 上位机 → UDP 到板子"：数据到了板子，格式初看像骨骼（`Bones`），实际完整包里 `Parameter` 数组就是 **l0~l22**，解析器兼容。
- 用户下载了 **HandDriver Web 版**（`HDW-Regular_v2.3.1_Ubuntu20+_arm_64.zip`）——B/S 架构、支持 Ubuntu/ARM → 可部署在板子上，实现自包含。

### Phase 5：HandDriver Web 部署（重点，走"轻量部署"省 20~40 分钟）

- **审查官方 `deploy_en.sh`**：它会 `apt` 装 boost/opencv/dlib/fltk + 从源码编译 protobuf 3.12.4（共约 20~40 分钟）。
- **用 `ldd` 查了 HDService 二进制**：运行时**只需要 `libprotobuf.so.23`**（其余 libcurl/标准库板子上已有）！opencv/dlib 那堆是编译期用的，运行时不需要 → **跳过重安装**。
- 补 `libprotobuf.so.23` 的过程（踩了两次坑）：
  1. github 直连太慢（国内网络）→ 换 **gh-proxy.com 代理**下载 `protobuf-cpp-3.12.4.tar.gz`。
  2. 清华镜像的 `libprotobuf23` deb 是 jammy 编的，**要 GLIBC_2.34，focal 只有 2.31**，用不了 → 只能源码编译。
  3. 源码编译 protobuf 3.12.4（`--prefix=/home/ubuntu/protobuf3124`，只编 cpp，约 5~8 分钟）→ 得到 `/home/ubuntu/protobuf3124/lib/libprotobuf.so.23`。
- HDService 二进制**没有执行权限**（`-rw-rw-rw-`）→ `chmod +x`。
- HDService 的 RUNPATH 指向 `/home/ubuntu/Projects/MoStream_HDW/lib:/usr/local/lib`（开发者路径不存在）→ 必须用 `LD_LIBRARY_PATH` 指定库目录。
- Web 客户端部署：`sudo bash deploy_en.sh -m client -y`（只装 nginx + 网页，约 2~3 分钟）→ 页面 `http://192.168.110.44:8088/` ✅。
- udev 规则：`80-usb-serial.rules` 拷到 `/etc/udev/rules.d/`（串口 0666，省掉 dialout）。

### Phase 6：端到端验证

1. 接收器从 Windows 挪到板子 → HDService 识别两只手套（`ABSTCE5FH004580L`/`...R`）。
2. Web 界面把 UDP 数据发送目标设为 `127.0.0.1:8000`。
3. 板子上监听 8000：数据来自 `127.0.0.1`（真实数据）+ `192.168.110.70`（Windows 旧上位机空包）→ **发现"非常抖"的根因**（见 Bug 9）。
4. 关闭 Windows 上位机 → 控制正常 ✅。

## 2. 遇到的 Bug 汇总（按顺序）

| #   | 现象                                                                                  | 根因                                                                                                                   | 解决                                                                                    |
| --- | ----------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| 1   | Python 3.8 import 报 `TypeError: 'type' object is not subscriptable`                 | `core.py` 的 `tuple[bool, str]` 注解是 3.9+ 语法                                                                           | 改为 `-> tuple`                                                                         |
| 2   | `ls /dev/ttyUSB*` 找不到串口                                                             | CH343 在 Linux 是 **CDC ACM**，叫 `/dev/ttyACM0`                                                                         | 用 `ls /dev/ttyACM*`；config.yaml port 填 `/dev/ttyACM0`                                 |
| 3   | 串口打不开/无权限                                                                           | `ubuntu` 不在 `dialout` 组                                                                                              | `sudo usermod -aG dialout ubuntu`（重登生效，或 `sg dialout -c`）                             |
| 4   | `HDService: 权限不够`                                                                   | 解压出的二进制 `-rw-rw-rw-`，没有 x 位                                                                                          | `chmod +x HDService`                                                                  |
| 5   | jammy 的 `libprotobuf.so.23` 用不了                                                     | jammy 编的需要 **GLIBC_2.34**，focal 只有 2.31                                                                              | 不装 deb，改**源码编译** protobuf 3.12.4                                                      |
| 6   | github 下载源码龟速                                                                       | 国内网络访问 github 慢                                                                                                      | 用代理 `https://gh-proxy.com/<github url>`（~115KB/s 可用）                                  |
| 7   | HDService 找不到自带的库                                                                   | RUNPATH 指向开发者路径 `/home/ubuntu/Projects/MoStream_HDW/lib`（不存在）                                                        | 启动时 `LD_LIBRARY_PATH=/home/ubuntu/protobuf3124/lib:<HDService>/lib`                   |
| 8   | 遥操"很卡"（第一次，接收器在 Windows）                                                            | ① WiFi 网络链路抖动 ② FeiTech 总线每帧全读（`read_pos_vel_cur` 含 17 次逐电机 `ReadCur`）拖慢控制频率 ③ 平滑系数 0.3                              | 上位机挪到板子本地（消除网络跳）；总线瓶颈见下方"性能备注"                                                        |
| 9   | 遥操"非常抖"（数据高频抖动）                                                                     | **Windows 旧上位机没关**：无手套数据后仍以 ~124Hz 发 `{}` 空包，与板子真实数据（~124Hz）1:1 交替。解析器收到 `{}` 会把全部关节数据清成 0，下一包又填回 → 手在"真角度⇄中性位"间高频振荡 | 关闭 Windows 上位机（HDService.exe / 旧网页）                                                   |
| 10  | ROS2 节点 `hand_controller` 在 mock 模式下崩溃：`ParameterNotDeclaredException: skip_joints` | `skip_joints` 参数只在 `if not self.mock:` 分支里声明，但 `_cb` 回调无条件 `get_parameter` 读取                                        | 把 `skip_joints` 声明挪到 mock 判断外（`_cb` 无论 mock 与否都要读它）                                   |
| 11  | ROS2 真链"稍微有点延迟" + 串口读错误（`Incorrect status packet`）                                  | FeiTech 总线每帧全读含 **17 次逐电机 `ReadCur`**，在 ARM 板子上单帧读 ~30ms，回调一慢就排队 → 延迟 + 读错误                                          | 给 `hl_client` 读函数加 `skip_current` 参数，`core.py get_motor_pos` 热路径跳过电流读 → 单帧读降到 ~5ms，顺滑 |

> **电机排查结论（2026-08-13）**：对 motor 8/13/15 单独读（6s，281 次/电机）和全 17 电机满载读（6s，240 次/电机）均 **100% 成功、0 失败、位置稳定**。结论：motor 15（index_mcp）硬件正常，"index 不跟手"不是电机故障；真链里偶发的 `Bulk read data unavailable [13,15]` 是**半双工总线上读/写交替时的瞬时时序冲突**（`_set_motor_pos` 先全读再写），良性——读失败回退缓存位置、写命令照常下发，不影响移动。`skip_current` 优化已把错误从满屏降到个别。

### 关于"卡/抖"的详细解释

- **很卡（网络链路时）**：数据要跨 WiFi（Windows→板子），UDP 有抖动和丢包；且板子每帧控制前会同步全读总线（含 17 次逐电机 `ReadCur`），把 60Hz 控制频率压低了。上位机搬到板子上走 `127.0.0.1` 后，网络那部分消除。
- **非常抖（自包含后）**：不是网络，是**两个 UDP 源同时在发**——板子的真实数据 + Windows 残留的 `{}` 空包。解析器对 `{}` 的副作用是"清空全部关节值"，于是数据在真实值⇄0 之间 ~124Hz 交替，teleop 每帧可能读到 0 → 手抖。**根因就是 Windows 上位机没关**，关掉即好。

### 性能备注（后续想提速可做）

- `hl_client.py` 的 `read_pos_vel_cur()` 每次读全部 17 个电机位置/速度/电流（`ReadCur` 逐电机），且 `_set_motor_pos` 每次写前都全读一次。遥操热路径若只读 pos+vel、不读电流，能显著提高控制频率。

## 5. ROS2 阶段关键命令（板子上）

```bash
source /opt/ros/foxy/setup.bash
source ~/fthand_ws/install/setup.bash

# 重建包（改了节点代码后）
cd ~/fthand_ws && colcon build --packages-select orcahand_teleop_ros2 --symlink-install

# 一键起真链（推荐，参数化 launch）：
ros2 launch orcahand_teleop_ros2 single_pc.launch.py
#   可选参数：use_fake_glove:=true（假手套） mock:=true（不碰硬件安全干跑）
#            hand:=right model_path:=.../orcahand_v1_right

# 三终端真链（等价手写版，左手，skip pinky_abd）
ros2 run orcahand_teleop_ros2 glove_driver
ros2 run orcahand_teleop_ros2 retargeter --ros-args -p hand:=left \
  -p model_path:=/home/ubuntu/FThand/FThand/FT_core/orca_core/models/orcahand_v1_left
ros2 run orcahand_teleop_ros2 hand_controller --ros-args -p mock:=false \
  -p model_path:=/home/ubuntu/FThand/FThand/FT_core/orca_core/models/orcahand_v1_left \
  -p skip_joints:=pinky_abd
```
