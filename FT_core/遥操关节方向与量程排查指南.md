# 遥操中关节方向反了 / 行程很小 —— 排查与修复指南

> 本文以右手 `index_abd`（食指外展，舵机 14）的一次完整排查为例，整理「为什么会出现方向反 / 行程小」「怎么判断」「怎么改」。同样的方法适用于任意关节。

---

## 0. 现象

遥操时发现：

1. **方向反**：食指外展时，机器人食指内收（反着来）。
2. **行程很小、看不出正负**：关节只在一个小范围内动，分不清到底往哪边才是对的。

这两件事其实是**两个独立的原因**叠加，要分开处理。

---

## 1. 背景知识：关节方向由「两层」共同决定

这是理解问题的前提。从手套到舵机，方向经过两层，**每层都有一个独立的"方向开关"**：

| 层        | 配置文件                                                                           | 控制什么              | 方向开关                              |
| -------- | ------------------------------------------------------------------------------ | ----------------- | --------------------------------- |
| **机器人层** | `orca_core/models/<手>/config.yaml` 的 `joint_to_motor_map` + `calibration.yaml` | 「命令 +角度 ⇨ 物理往哪边动」 | `joint_to_motor_map` 里舵机号的**正负号** |
| **遥操层**  | `orca_core/models/<手>/glove_mapping.yaml`                                      | 「手套动作 ⇨ 命令正负角度」   | `invert` 字段、`direction` 字段        |

### 1.1 `joint_to_motor_map` 正负号的含义（机器人层）

```yaml
joint_to_motor_map:
  index_abd: -14     # 食指外展接到 14 号舵机
```

- **绝对值 = 舵机 ID**：`-14` 就是 14 号舵机。
- **正负号 = 该关节方向是否取反**（`orca_core/core.py` 里解析成 `joint_inversion_dict`）：
  - 正号：关节角度增大 ⇨ 舵机位置增大；
  - 负号：关节角度增大 ⇨ 舵机位置减小。
- 改了这里的符号，**必须重新标定该关节**（标定时会按符号决定往哪个方向推、把极限记到 `motor_limits[0]/[1]`）。

### 1.2 `glove_mapping.yaml` 的关键字段（遥操层）

```yaml
index_abd:
  glove_var: r7          # 手套变量
  component: y           # 用 x/y 分量
  range_min: -23         # ← 量程下界（决定 normalized 大小）
  range_max: 0           # ← 量程上界
  neutral: 0
  factor: 1.2            # 运动系数
  direction: inward      # inward=负值范围 / outward=正值范围 / bidirectional=双向
  invert: false          # ← 方向反转开关（true 则把 normalized 取反）
```

遥操层的角度计算（简化）：

```
normalized = 手套原始值 / 量程        # 范围大致 [-1, 1]
if invert: normalized = -normalized
angle = neutral + normalized × (rom 距离) × factor × motion_scale
```

所以：

- **量程（range_min/max）** 决定 `normalized` 能多大 → 决定**行程大小**。
- **invert / direction** 决定 `normalized` 的符号 → 决定**方向正负**。
- **factor / motion_scale** 是整体放大倍数。

> ⚠️ 关键原则：**两层各有一个方向开关，一次只改一层、改完测一次**，别两层同时乱拨，否则会变成"双重取反"搞不清状态。

---

## 2. 为什么会出现这些问题

### 2.1 方向反

- 两层的"方向开关"没有对齐：机器人层把"+角度"理解成某个物理方向，遥操层把"手套外展"映射成了另一个符号，两者一组合就反了。
- 本例特别容易踩坑：`index_abd` 配成了 `direction: inward`（读手套 y<0），而其它三个外展关节（middle/ring/pinky_abd）都是 `outward`（读 y>0），存在不对称。
- 另外 `invert` 一旦设错，或机器人层符号翻过一次又叠加 `invert`，都会反。

### 2.2 行程很小 / 看不出正负

- **量程没对上**：`range_min/max` 写得比手套实际输出范围宽（例如写 -25，实际只到 -23 甚至更小），导致 `normalized` 始终是个小数，命令角度一直贴着中立点。
- **factor 当补偿硬拉**：有人为了让小行程"看起来够大"，把 `factor` 调得很高（本例原 1.56）。结果在行程末端猛地跳到 100%，中间段却几乎是空的——既像"行程小"，又像"看不出方向"。
- **手套单向输出**：手套某个变量只往一个方向变（本例 r7-y 只走 0→-23，永不为正），关节就只能从中立点单向跑，没有来回对比，自然"看不出正负"。

## 3. 怎么判断（诊断流程）

### 第一步：分清是哪一层的问题

用 `slider_joint.py` 直接命令关节角度（**绕开手套**），隔离机器人层：

```sh
python scripts\slider_joint.py orca_core\models\orcahand_v1_right
```

把 `index_abd` 滑块拖到**正值**，看食指物理上是不是**外展**：

- 是 → 机器人层 OK，问题在遥操层。
- 反（内收）→ 机器人层就反了，去改 `config.yaml` 符号 + 重标定。

> 同时也能顺便确认标定有没有成功：看 `calibration.yaml` 里该舵机的 `motor_limits` 两个值差距是否足够大。差距≈0 说明标定时电机没动（假达标），物理行程会很小。本例 servo 14 为 `[-1.074, 0.383]`，差 1.46 rad≈83°，健康。

### 第二步：遥操层用运行时命令诊断

启动遥操后，它自带一套命令（输入后回车）：

| 命令          | 作用                                              |
| ----------- | ----------------------------------------------- |
| `p`         | 打印一次诊断快照：每个关节的 `raw → normalized → 位置% → angle` |
| `d`         | 开/关 每 2 秒自动诊断                                   |
| `c`         | **开始/停止 量程探测**：戴手套做满幅度动作，自动给出实测 min/max 和建议量程   |
| `s<数>`      | 临时改整体运动缩放（0~1），如 `s1.0`                         |
| `f<关节> <数>` | 临时改单关节系数，如 `f index_abd 1.2`                    |
| `n`         | 回中性位                                            |

#### 判读口诀（诊断输出底部自带）

- `raw≈0 且不动` = 映射错 / 没收到手套数据；
- `normalized 很小` = `range_min/max` 太宽 → 用 `c` 探测；
- `位置% 很低` = 用 `s` / `f` 放大；
- 探测表里出现 `⚠ 实测非负, 可能 direction/glove_var 配反` = 方向符号配反。

### 第三步：用 `c` 探测拿到 ground truth

`p` 只是瞬时快照，`c` 才能给全程的实测范围：

1. 输入 `c` 开始；
2. 戴好手套，把目标关节**慢慢做到底、重复 2~3 次**（顺便五指张握，把所有关节都探了）；
3. 再输入 `c` 结束，得到一张表：

```
右:index_abd   实测[-23,0]   当前[-25,0]   建议 min=-23, max=0
```

这张表同时回答两件事：**量程该填多少**（建议列）和 **方向有没有配反**（⚠ 标志）。

## 4. 怎么改

### 4.1 修量程（行程小 / normalized 小）

把 `c` 探测的「建议」填回 `glove_mapping.yaml` 对应关节的 `range_min / range_max`，然后把 `factor` 调回 ~1.0–1.2（去掉之前的补偿）。满幅度时 normalized 应能接近 ±1，无需靠高 factor 硬撑。

> 经验：满展时 `normalized × factor × motion_scale ≈ 1` 即可铺满 ROM。本例 `1.0 × 1.2 × 0.8 ≈ 0.96`，接近满行程。

### 4.2 修方向（遥操层，**不用重标定**）

这是最快的方式。核心是搞清两件事：

1. **手套外展时 raw 是正还是负** → 决定 `normalized` 的符号；
2. **机器人 `rom_max`/`rom_min` 哪个是物理外展** → 决定该往哪边跑。

然后让"外展 → 外展方向"成立。判定方法：戴手套做一个明确的外展动作，用 `p` 看 normalized 符号和命令角度方向，再对照机器人实际运动。

- 方向反了 → 切换 `invert: true/false`（一行改动，可逆）。
- 也可以改 `direction`（inward↔outward）并相应翻转量程正负，但通常拨 `invert` 更省事。

### 4.3 修方向（机器人层，**需重标定**）

仅当第一步判定机器人层本身就反时才动这里：

1. 翻 `config.yaml` 里该关节的符号（如 `index_abd: -14` → `14`）；
2. 重新标定该关节（用单关节标定，避免重跑全量）：
   
   ```sh
   python scripts\calibrate.py orca_core\models\orcahand_v1_right --joint index_abd
   ```

## 5. 本次实际改动记录（右手 `orcahand_v1_right`）

### 5.1 `glove_mapping.yaml`

| 关节           | 改动                                                                  | 原因                                                                                    |
| ------------ | ------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| `index_abd`  | `range_min` -25→**-23**；`factor` 1.56→**1.2**；**删除 `invert: true`** | 探测实测 min=-23；量程收紧后去掉 1.56 补偿；用户实测「外展时机器人内收」，删 invert 让 normalized 为负、跑向 rom_min（外展方向） |
| `middle_abd` | `range_max` 6→**2**                                                 | 探测实测 max=2，原 6 把量程压成 1/3                                                              |
| `thumb_dip`  | `range_min` -42→**-60**                                             | 探测实测到 -60，原 -42 提前饱和                                                                  |

其余关节实测与原 range 基本吻合，未改。

### 5.2 index_abd 方向的推理链（worked example）

1. 诊断快照：手套外展时 `raw=-19.4`，当时 `invert:true` → `normalized=+0.78` → 命令 `+36.5°`（rom_max 方向）。
2. 用户反馈：此时机器人**内收**（反的）。
3. 推断：对该手 **rom_max = 内收方向**，因此 **rom_min = 外展方向**。
4. 要让"外展→外展"，需让 normalized 为负（跑向 rom_min）→ **删除 `invert`**。
5. 删后：`raw=-23`（满展）→ `normalized=-1.0` → 命令 `≈-35.5°`（rom_min，外展）✓。

### 5.3 涉及的代码改动（本次排查中顺带做的）

- `scripts/tension.py`：连接失败时打印 `status[1]` 真实原因；新增 `--continuous` 持续张紧选项。
- `scripts/calibrate.py`：新增 `--joint` 单关节标定。
- 这些与方向/量程无关，是为排查过程提供工具。

---

## 6. 已知局限

手套某些变量只单向输出（如 r7-y 只走 0→-23），对应关节**只能单方向运动**（只能外展、不能内收）。这是手套硬件的单向性，不是 bug；机器人会忠实跟随手套能给出的那一个方向。

---

## 7. 速查清单

出现「方向反 / 行程小」时，按顺序：

- [ ] `slider_joint.py` 拖目标关节正值 → 物理方向对吗？（分清机器人层/遥操层）
- [ ] 看 `calibration.yaml` 该舵机 `motor_limits` 差距是否够大（排除假标定）
- [ ] 遥操里 `p` 看 `normalized` 是否很小（量程问题）
- [ ] 遥操里 `c` 探测，把建议量程填回 `glove_mapping.yaml`，factor 调回 ~1.0–1.2
- [ ] 戴手套做明确动作 + `p`，判定 `rom_max/rom_min` 哪个是想要的方向
- [ ] 方向反 → 切 `invert`（遥操层，免标定）；机器人层反 → 翻 `config.yaml` 符号 + `calibrate.py --joint`
- [ ] 重启遥操验证
