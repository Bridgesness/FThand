## 0. 项目全景与最终架构

```
数据手套(UDEGlove) ─蓝牙→ 接收器(CH340) ─USB→ HDService(上位机,解析成关节角)
                                                    │ UDP 127.0.0.1:8000
                                                    ▼
                        [glove_driver] 收UDP → 发 /glove/data (90个float)
                                                    │
                                                    ▼
                        [retargeter] 映射+平滑 → 发 /hand/joint_targets (16个手指关节角)
                                                    │
                         ┌──────────────────────────┴─────────────────────────┐
                         ▼                                                      ▼
              [hand_controller] 控真手舵机(FeiTech)                [record_combined] 数采
                         ▲                                                      │
                         │ 回放                                                   │
              [replay_targets/sync/combined] 读CSV→发 → 手/臂重做                ▼
                        traj_*.csv (带时间戳动作轨迹, 供VLA)
```

OpenARM 双臂接入：机械臂关节角 → `/joint_states`，`record_combined` 把机械臂 + 手合成 **33 维动作轨迹**。

## 一、第一阶段：灵巧手跟手调优（串口瓶颈，最难的一环）

### 1.1 现象与排查
- 现象：遥操时手跟手套有明显延迟、甚至卡顿抖动。
- 排查命令：逐次计时确认瓶颈
  ```bash
  python3 - <<'PY'   # 在板子上
  import sys, time
  from orca_core.core import OrcaHand
  h = OrcaHand(model_path=...)
  h.connect(); h.enable_torque(); h.set_control_mode('current_based_position')
  ang = h.get_joint_pos(as_list=False)
  for i in range(5):
      t0=time.time(); h.set_joint_pos(ang, num_steps=1); print(f'{(time.time()-t0)*1000:.1f}ms')
  PY
  ```
- 结果：`get_motor_pos≈8ms`、`set_joint_pos≈15ms`。

### 1.2 根因
`_set_motor_pos` 每次写前都 `get_motor_pos()` 全读总线，FeiTech 的 `read_pos_vel_cur()` 含 **17 次逐电机 `ReadCur`**（电流读取），是主要耗时。60Hz（16.6ms/帧）只够一次写入，必然排队 → 延迟。

### 1.3 代码修改（伪代码）
```python
# hl_client.py: HLPosVelCurReader.read
def read(self, retries=1, skip_current=False):
    pos_vel = super().read(retries)          # 同步读 pos+vel（快）
    if skip_current:
        return pos_vel                        # ★遥操热路径跳过电流，省 17 次串口往返
    for motor in self.motor_ids:             # 只有标定/张紧才读电流
        cur = ReadCur(motor)

# core.py: get_motor_pos
motor_pos = self._dxl_client.read_pos_vel_cur(skip_current=True)[0]
```

### 1.4 效果
- 控制环 CPU：**85% → 45%**。
- 同时把控制频率从 60Hz 降到 **30Hz**（安全值，匹配串口延迟预算 15ms×30=45% 负载）。

### 1.5 需要补足的概念
- 串口是**半双工**独占资源；`GroupSyncRead`/`GroupSyncWrite`（一次读写多个电机）；bus 时序。
- "控制频率 vs 执行层延迟预算"的匹配原则。

### 1.6 端到端延迟预算（实测，2026-08，Jetson）

| 环节 | 延迟 |
|---|---|
| UDP 本地到达 | ~0.1ms |
| 30Hz 采样 | **平均 16.7ms**（主导）|
| retargeter 处理 | 平均 2.3ms（p95 5.7ms）|
| DDS | ~1ms |
| set_joint_pos 串口 | 平均 7.1ms |
| **端到端指令延迟** | **≈27~30ms** |

> **重要认知**：延迟主导项是**采样率**（16.7ms），不是串口或处理。串口优化（skip_current：15ms→7.1ms）+ 降频（60→30Hz）后整体平衡。若要更低延迟需提频率，但受串口预算限制——形成"采样率 vs 串口预算"权衡曲线。

### 1.7 原理深挖：平滑其实是低通滤波（解释"跟不上"）

`SmoothController`：`y[n]=α·x[n]+(1-α)·y[n-1]`，α=0.3
- 这是一阶 IIR 低通。时间常数 τ=(1-α)/(α·fs)≈0.078s，**截止频率 fc≈2Hz**。
- 含义：手能跟上的最高频率约 2Hz——**这才是"跟不上快速手势"的真正原因**（比串口更根本）。
- 调参：α 越大越跟手（fc 高）但噪声越多；α 越小越稳但越钝。

### 1.8 实测跟踪误差（2026-08，Jetson）
典型关节 **0.1~1°**（伺服精度好）；**thumb_pip 离群 max 16°**（肌腱松弛/传动间隙假说）。

## 二、第二阶段：PC(Windows/WSL) → RK3588 移植

### 2.1 环境差异（关键）
| 项 | PC/WSL | RK3588 |
|---|---|---|
| ROS2 | Humble | **Foxy** |
| Python | 3.10 | **3.8** |
| 架构 | x86_64 | ARM64 |

### 2.2 卡点与修复
1. **Python 3.8 语法崩溃**：`orca_core/core.py` 的 `-> tuple[bool, str]` 注解是 3.9+ 语法，3.8 import 即报 `TypeError`。
   ```python
   # 修复：改成裸 tuple（3.8 合法，语义不变）
   def connect(self) -> tuple:
   ```
2. **串口是 ttyACM 不是 ttyUSB**：CH343 在 Linux 是 CDC ACM → `/dev/ttyACM0`（不是 `ttyUSB0`）。
3. **串口权限**：用户不在 `dialout` 组 → `sudo usermod -aG dialout $USER`。
4. **上位机（HDService）部署**：见下。

### 2.3 HDService（HandDriver Web 上位机）部署——依赖最小化
- **卡点**：vendor 的自动部署脚本要装 boost/opencv/dlib + 从源码编译 protobuf（30~40 分钟）。
- **突破口**：`ldd HDService` 分析发现运行时只需要 `libprotobuf.so.23`（其余都是系统库）。
- **做法**：自行编译 protobuf 3.12.4（`./configure --prefix=~/protobuf3124 && make -j`）→ `LD_LIBRARY_PATH` 指过去。
- **伪代码**：
  ```bash
  ldd HDService | grep "not found"        # 只有 libprotobuf.so.23
  ./configure --prefix=$HOME/protobuf3124 && make -j$(nproc) && make install
  export LD_LIBRARY_PATH=$HOME/protobuf3124/lib:.../HDService/lib
  ./HDService
  ```
- 启动脚本 `run_hdservice.sh`（含 LD_LIBRARY_PATH + cd）。

### 2.4 需要补足的概念
- `ldd`/`readelf -d NEEDED`（动态依赖分析）；`LD_LIBRARY_PATH` vs RPATH；`dpkg -x`（解包 deb 拿库）。
- udev 规则、systemd 服务、`.bashrc`/`.profile`。

## 三、第三阶段：数采与回放（ROS2 节点化）

### 3.1 节点设计（每个节点的作用）
| 节点 | 作用 |
|---|---|
| `glove_driver` | 收 UDP 8000 → 发 `/glove/data` |
| `retargeter` | 映射+平滑 → 发 `/hand/joint_targets` |
| `hand_controller` | 订阅 → `set_joint_pos` 控真手 |
| `record_targets` | 订阅 `/hand/joint_targets` → 存 CSV |
| `replay_targets` | 读 CSV → 发 `/hand/joint_targets` |
| `record_combined` | 订阅 `/joint_states`(臂) + `/hand/joint_targets`(手) → 存合并 CSV |
| `replay_combined`/`replay_sync` | 合并/同步回放（臂+手） |

### 3.2 关键代码（伪代码）
```python
# record_targets 核心
def _sample(self):                          # 30Hz 定时
    msg = self._last                        # 最新 JointState
    self.rows.append([timestamp_ms] + msg.position)

def save(self):                              # Ctrl+C / duration 触发
    write CSV(headers + rows)                # timestamp_ms, j0..j15

# replay_targets 核心 + 安全限速
def _publish(self, angles):
    angles = clamp_step(self._prev, angles, max_step=3.0)  # ★限速防抽搐
    publish JointState(name, angles)

# replay_sync：机械臂合成摆动 + 手轨迹同步
def _publish_frame(self, t_rel, hand):
    left = amp*sin(2π*freq*t_rel + phase)    # 模拟键盘输入，驱动机械臂
    publish arm trajectory + hand JointState
```

### 3.3 安全限速（重要教训）
- 教训：无限制回放快速 CSV 会让手暴力抽搐（有惊无险）。加 `max_step`（每帧最大关节变化）削峰。
  ```python
  def clamp_step(prev, target, max_step):
      return [p + max(-max_step, min(max_step, t-p)) for p,t in zip(prev,target)]
  ```
- 排查"手不动"：分层验证（日志→串口→单关节→全关节→重启干净实例），发现是**旧进程被并发访问污染**，重启解决。

### 3.4 需要补足的概念
- ROS2 节点/话题/参数/launch；`LaunchConfiguration` vs 字面量（布尔参数坑）；Jazzy 参数类型严格。
- CSV 数据格式设计（时间戳对齐 observation）。

## 四、第四阶段：RK → Jetson(AGX Orin) + OpenARM 协同

### 4.1 Jetson 环境
| 项 | 值 |
|---|---|
| 系统 | Ubuntu 24.04 / Python 3.12 |
| ROS2 | **Jazzy** |
| 图形 | 桌面 + DP 显示器（rviz 用 `DISPLAY=:1`） |

### 4.2 卡点与修复
1. **OpenARM(Humble) 在 Jazzy 上编译**：
   - `openarm_can` 缺 CLI11 → `apt install libcli11-dev`。
   - `openarm_hardware` 用 ros2_control 旧 API → 只有弃用警告，能编。
   - `openarm_bringup` 依赖 MoveIt（实际 launch 不用）→ 移除该 exec_depend。
2. **Python 3.12 + colcon**：
   - `distutils` 移除 → 装 setuptools；**84 太新破坏 `develop --uninstall`** → 降到 **69.5.1**（两者兼容）。
3. **Jazzy 参数类型严格**：`-p duration:=8`(int) 赋给 double 参数报错 → 按整数声明。

### 4.3 OpenARM 模拟与遥操
- 模拟：`use_fake_hardware:=true`（ros2_control fake hardware，不碰真硬件）。
- 可视化：rviz（`bimanual.rviz`）。
- 键盘遥操：`ros2 run vla_collection bimanual_teleop`（菜单选臂、按键动关节）。
- 外骨骼遥操：CANSocket 直读 leader，1000Hz MIT 力反馈（真硬件时）。

### 4.4 合并数采（协同）
- `record_combined`：机械臂 `/joint_states` + 手 `/hand/joint_targets` → **33 维** CSV（左臂7+夹爪+右臂7+夹爪+手16+时间戳）。
- 回放：`replay_sync`（合成臂摆动 + 手轨迹同步）。

### 4.5 需要补足的概念
- ros2_control（hardware_interface、controller_manager、joint_trajectory_controller）；SocketCAN；MIT 控制；MoveIt（可选）。

## 五、难点卡点汇总表

| 卡点 | 现象 | 根因 | 解决 |
|---|---|---|---|
| 遥操卡顿 | 手跟手套延迟 | 串口每帧全读含 17 次电流读 | `skip_current` 优化 |
| 手高频抖 | 真角度⇄中性位振荡 | 上位机空包 `{}` 清零状态 | 关 Windows 上位机 |
| 回放命令到了手不动 | 日志正常、硬件不动 | 进程被并发访问污染 | 重启干净实例 |
| 手暴力抽搐 | 快速 0↔95° 跳变 | 回放无限速 | 加 `max_step` 限速 |
| 板子超卡 | 整机卡死 | 板子 Chromium 跑 WebGL | 监控改 Windows |
| 串口变号 | ttyACM0→3 | USB 拔插重枚举 | udev 固定软链接 |
| Python 3.8 崩 | import 报错 | `tuple[bool,str]` 3.9 语法 | 改裸 `tuple` |
| Jazzy 编不过 | colcon 报错 | 依赖链 + Python3.12 | CLI11/setuptools 69.5.1/去 MoveIt |

## 七点五、方案对比与设计决策（为什么这么做）

| 维度 | 我的方案 | 备选 | 为什么选这个 |
|---|---|---|---|
| 遥操输入 | 数据手套（关节角直接） | 视觉(MediaPipe/Leap)、外骨骼 | 手套给关节角最直接、延迟低；视觉要估计受遮挡；外骨骼贵、复杂但有力反馈 |
| 控制架构 | ROS2 3 节点 + launch | 单进程 / ros2_control 全栈 | 模块化可插拔（换算法只换 retargeter）；单进程难扩展 |
| 记录格式 | CSV 带时间戳 | HDF5 / ros2 bag | CSV 简单可读、pandas 直接；HDF5 高效但依赖库；bag 是原始流 |
| 可视化 | ros2_control fake + rviz | Gazebo | OpenARM 官方即 fake+rviz；Gazebo 需重建物理属性，对链路验证非必要 |
| 执行层 | 飞特舵机自写 client | Dynamixel | 项目硬件；client 抽象层已兼容两种 |
