## 1. 这是什么：最终架构

一句话：**戴上手套动手指，机器手跟着动**，整个系统跑在板子上，不用电脑。

```
┌────────────────────────────── 板子 RK3588 上 ─────────────────────────────┐
│                                                                          │
│  数据手套 ─蓝牙→ 接收器(USB) → HDService(手套服务端, UDP:8000)             │
│                                        │                                  │
│                                        ▼                                  │
│   [glove_driver] ─/glove/data→ [retargeter] ─/hand/joint_targets→ [hand_controller]→ 灵巧手
│     收UDP+发布          (Float64MultiArray)   映射+平滑  (JointState)        订阅+控舵机     │
│                                                                          │
└──────────────────────────────────────────────────────────────────────────┘
```

三个 ROS2 节点各司其职：

- **glove_driver**：收手套 UDP 数据（90 个 float），发布到 `/glove/data`
- **retargeter**：把 90 个 float 映射+平滑成 17 个关节角度，发布到 `/hand/joint_targets`（可插拔：换算法只换它）
- **hand_controller**：订阅关节目标，驱动飞特舵机（控制真手）

## 2. 硬件准备

| 东西    | 接法/注意                            |
| ----- | -------------------------------- |
| 灵巧手   | USB 串口线插板子，`/dev/ttyACM0`（CH343） |

## 3. 开机即用

**开机后只有手套服务端（HDService）自动启动**；ROS2 遥操**需要手动起**——这是故意这么配的：防止上电时机器手自己跟着手套动。

**流程：**

1. 开机，插好接收器 + 手 + 戴好手套
2. 等 ~20 秒（HDService 自动起来）
3. **手动**起 ROS2 真链，此时才开始控手：

```bash
# 确认手套服务端已自动起来（应输出 active）
systemctl is-active hdservice

# 手动起 ROS2 真链（一条命令，3 节点全起）
ros2 launch orcahand_teleop_ros2 single_pc.launch.py
```

> 用**板子本地终端**的话，**要新开一个终端**（旧终端没加载环境）。`.bashrc`/`.profile` 已配好自动 source 工作空间，新终端直接能用 `ros2`；若偶尔报"找不到包"，先跑 `source ~/fthand_ws/install/setup.bash`。

确认节点都起来了（另开一个终端 ssh 上去）：

```bash
ros2 node list   # 应看到 /glove_driver /retargeter /hand_controller
```

用完 `Ctrl+C` 停掉 launch 即可；手套服务端保持运行无妨。

### 3.1 Windows 网页监控（看手模型/效果）

HandDriver Web 是 B/S 架构，网页可在局域网内任何浏览器打开。**用 Windows 电脑的 Chrome 打开**：

```
http://192.168.110.44:8088/
```

- 实时显示手模型/数据（跟手套动），**渲染在你电脑上做**，板子只发数据 → 流畅
- ⚠️ **别在板子自带的浏览器里开这个网页**：Unity WebGL 3D 渲染会占满板子 CPU（实测 ~200%），导致网页和板子系统都卡
- ⚠️ **遥操时建议关掉这个网页**：HDService 是单进程，网页连在远端（WiFi）会拖慢它给遥操发的 UDP → 手控制出现延迟。网页只用于配置/短暂看效果，看完就关

### 3.2 录制动作（数采）

**方式 C（最简，推荐）**：遥操 + 录制合并成一条 launch，Ctrl+C 停时自动保存：

```bash
ros2 launch orcahand_teleop_ros2 single_pc.launch.py record:=true
#   手动录到 Ctrl+C；固定时长用 record:=true record_duration:=10
```

**方式 A/B（分开跑）**：跑着遥操时另开终端单独录：

```bash
# 方式A：手动录，Ctrl+C 停止并保存
ros2 run orcahand_teleop_ros2 record_targets

# 方式B：录固定时长（如 10 秒）自动保存
ros2 run orcahand_teleop_ros2 record_targets --ros-args -p duration:=10
```

- 录制的是 **`/hand/joint_targets`**（下发到手的关节角轨迹，16 个手指关节），默认 30Hz、带时间戳
- 文件存到 `~/fthand_ws/data/traj_<时间>.csv`，CSV 带注释头（关节名/采样率），可直接 `pd.read_csv` 做 VLA 数据
- 可选参数：`-p rate:=30`（采样率）、`-p outdir:=~/fthand_ws/data`（保存目录）

### 3.3 回放动作

1. **先停掉遥操链**（launch 终端 `Ctrl+C`）——避免 retargeter 和回放抢同一个话题
2. 一条命令回放（参数已写死，只需给 CSV 文件名）：

```bash
ros2 launch orcahand_teleop_ros2 replay.launch.py file:=/home/ubuntu/fthand_ws/data/traj_xxx.csv
```

- 手会按录制节奏重做一遍动作；循环回放加 `loop:=true`
- 数据流：CSV → `/hand/joint_targets` → hand_controller → 真手
- （等价手写版：`ros2 run ... hand_controller -p mock:=false -p model_path:=.../orcahand_v1_left` + `ros2 run ... replay_targets -p file:=...`，平时用 launch 即可）

### 3.4 数据流 & 命令详解（看明白用）

#### 数据是怎么流动的

```
[手套] --蓝牙--> [接收器 ttyACM1/2] --USB--> [HDService 手套服务端: 解析成关节角]
                                                  │  UDP 127.0.0.1:8000
                                                  ▼
                         [glove_driver]  监听UDP → 发布 /glove/data   (90个float，左右手各45)
                                                  │
                                                  ▼
                         [retargeter]   订阅 → 映射+平滑 → 发布 /hand/joint_targets  (16个关节角)
                                                  │
                          ┌───────────────────────┴────────────────────────┐
                          ▼                                                 ▼
                 [hand_controller]  订阅→控真手舵机              [record_targets] 订阅→存CSV(数采)
                          ▲
                          │  回放时
                 [replay_targets]  读CSV→发布 /hand/joint_targets
```

**核心**：`/hand/joint_targets` 是**中央总线**——

- **实时**：retargeter 写总线（手套映射结果）
- **录制**：record_targets 读总线（存关节角）
- **回放**：replay_targets 写总线（读 CSV），hand_controller 读总线 → 手重做

录/放只是"搭线"在这条总线上，不用改任何系统（ROS2 话题解耦的好处）。

#### 命令含义

| 命令                                           | 类型        | 含义                                                  |
| -------------------------------------------- | --------- | --------------------------------------------------- |
| `ros2 launch ... single_pc.launch.py`        | 起**多个**节点 | 起 glove_driver+retargeter+hand_controller 整条实时链（控手） |
| `ros2 run ... record_targets`                | 起**一个**节点 | 订阅 /hand/joint_targets 存 CSV（数采）                    |
| `ros2 run ... hand_controller ...`           | 起**一个**节点 | 单独控手（回放时用）                                          |
| `ros2 run ... replay_targets -p file:=x.csv` | 起**一个**节点 | 读 CSV 发布 /hand/joint_targets（回放）                    |

> `ros2 launch` 起多个节点；`ros2 run` 只起一个。节点分工：glove_driver=数据源、retargeter=加工、hand_controller=执行。

#### 终端分工

| 终端   | 跑的命令                                                             | 作用                             |
| ---- | ---------------------------------------------------------------- | ------------------------------ |
| 终端 1 | `ros2 launch orcahand_teleop_ros2 single_pc.launch.py`           | **实时遥操**：控手 + 产生数据源            |
| 终端 2 | `ros2 run orcahand_teleop_ros2 record_targets`                   | **录制**：把动作存成 CSV               |
| 终端 3 | `ros2 launch orcahand_teleop_ros2 replay.launch.py file:=...csv` | **回放**：手重做录的动作（先 Ctrl+C 停终端 1） |

## 4. 系统服务管理（systemd）

我们配了两个服务：

| 服务名               | 作用                  | 状态                        |
| ----------------- | ------------------- | ------------------------- |
| `hdservice`       | 手套服务端（接收器→UDP 8000） | **开机自启** ✅                |
| `orcahand-teleop` | ROS2 真链（3 节点）       | **手动启动**（故意不开自启，防止上电手自动动） |

常用管理命令（都加 `sudo`）：

```bash
sudo systemctl status  hdservice            # 看状态
sudo systemctl restart hdservice            # 重启

sudo systemctl start   orcahand-teleop      # 手动起遥操
sudo systemctl stop    orcahand-teleop      # 停遥操（手不再跟手套）
sudo systemctl status  orcahand-teleop      # 看状态

journalctl -u orcahand-teleop -f            # 实时看遥操日志
```

> 如果想改回"上电自动控手"：`sudo systemctl enable orcahand-teleop`（一般不建议——上电时手会跟着手套动）。日常更推荐上面那样手动 `start`/`ros2 launch`。

**systemd 是啥？** Ubuntu 的服务管理器，开机按 `.service` 文件拉起后台程序、崩溃自动重启（我们设了 `Restart=always`）、日志统一管理（`journalctl`）。配置文件在 `/etc/systemd/system/`。

## 8. ROS2 知识讲解（重点）

### 8.1 ROS2 是啥

机器人操作系统（不是真的操作系统），是**通信框架**：让多个程序（节点）之间用**话题/服务**互相发消息。用在这就是让"收手套的、做映射的、控舵机的"三个程序解耦、各跑各的。

### 8.2 核心概念

| 概念                 | 类比             | 本项目例子                                       |
| ------------------ | -------------- | ------------------------------------------- |
| **节点 (Node)**      | 一个独立运行的程序      | glove_driver / retargeter / hand_controller |
| **话题 (Topic)**     | 广播频道，发布者写、订阅者读 | `/glove/data`、`/hand/joint_targets`         |
| **消息 (Message)**   | 频道上传输的数据类型     | `Float64MultiArray`(90个float)、`JointState`  |
| **发布/订阅**          | 写/读频道，一对多、不等待  | glove_driver 发布，retargeter 订阅               |
| **参数 (Parameter)** | 节点可配置的键值       | `smoothing`、`hand`、`mock`                   |
| **服务 (Service)**   | 请求/响应（一问一答）    | `/hand_controller/neutral` 等                |
| **动作 (Action)**    | 长任务请求+反馈       | （本工程暂未用）                                    |

**本项目数据流**：

```
glove_driver(发布) --/glove/data(Float64MultiArray)--> retargeter(订阅+发布) --/hand/joint_targets(JointState)--> hand_controller(订阅)
```

### 8.3 消息怎么定义的

- `/glove/data` 是 `std_msgs/Float64MultiArray`：一个 `data` 数组，90 个 float = 左右手各 15 个关节 × 3 分量。
- `/hand/joint_targets` 是 `sensor_msgs/JointState`：带 `name`（关节名数组）+ `position`（角度数组），这样订阅方 `dict(zip(name, position))` 就能还原成"关节→角度"。

### 8.4 节点代码长啥样（rclpy）

最小的发布/订阅节点：

```python
import rclpy
from rclpy.node import Node
from std_msgs.msg import Float64MultiArray

class GloveDriverNode(Node):
    def __init__(self):
        super().__init__('glove_driver')                      # 节点名
        self.pub = self.create_publisher(Float64MultiArray, '/glove/data', 10)
        self.create_timer(1.0/60.0, self._tick)               # 60Hz 定时回调

    def _tick(self):
        msg = Float64MultiArray(); msg.data = [0.0]*90
        self.pub.publish(msg)                                  # 发布

def main():
    rclpy.init()
    rclpy.spin(GloveDriverNode())                              # 事件循环，别阻塞
    rclpy.shutdown()
```

要点：`create_publisher/Subscription` 注册频道，`create_timer` 定时回调，`spin()` 跑事件循环。订阅回调里**不能做耗时的事**（会卡住），本项目手忙就是因为回调里做了全总线读——已用 `skip_current` 优化。

### 8.5 launch：一键起多个节点

launch 文件 = 用 Python 描述"要启动哪些节点、带什么参数"：

```python
from launch import LaunchDescription
from launch.actions import DeclareLaunchArgument
from launch.substitutions import LaunchConfiguration
from launch_ros.actions import Node

def generate_launch_description():
    return LaunchDescription([
        DeclareLaunchArgument('mock', default_value='false', description='...'),
        Node(package='orcahand_teleop_ros2', executable='hand_controller',
             parameters=[{'mock': LaunchConfiguration('mock')}]),
    ])
```

- `DeclareLaunchArgument` = 声明可覆盖参数 → 启动时 `mock:=true`
- `LaunchConfiguration('mock')` = 运行时才取值
- 跑：`ros2 launch <包名> <文件名>.py [参数:=值]`
  本项目 `single_pc.launch.py` 就是参数化后的版本（`use_fake_glove`/`hand`/`model_path`/`mock`/`skip_joints`/`smoothing`）。

### 8.6 参数

节点里 `self.declare_parameter('smoothing', 0.3)` 声明，`self.get_parameter('smoothing').value` 读。运行时 `ros2 param set <节点> <名> <值>` 改，或 launch 里传。**注意**：参数要在用之前声明（我们在 `hand_controller` 踩过的坑：`skip_joints` 只在非 mock 分支声明，mock 时读它崩了）。

### 8.7 DDS 和 QoS（简）

- **DDS**：ROS2 底层通信中间件（本项目是 FastRTPS），负责节点发现 + 数据传输。节点自动互相发现，不需要配 IP。
- **QoS**：服务质量，`create_publisher(..., 10)` 那个 10 是队列深度（最多缓存 10 帧）。传感器数据追求低延迟可以用 `BEST_EFFORT`，丢几帧无所谓。

### 8.8 工作空间 / 包

```
fthand_ws/
├─ src/orcahand_teleop_ros2/    ← 一个 ROS2 包
│   ├─ orcahand_teleop_ros2/    ← 节点源码(.py)
│   ├─ launch/                  ← launch 文件
│   ├─ package.xml              ← 依赖声明(rclpy/std_msgs/sensor_msgs)
│   └─ setup.py                 ← 打包配置(entry_points 把节点注册成可执行)
├─ build/ install/ log/         ← colcon 产物
```

- `colcon build --packages-select <包> --symlink-install`：编译；`--symlink-install` 让改 .py 不用重编（软链）。
- `source install/setup.bash`：让系统"看到"这个包的节点（已写进 .bashrc）。

### 8.9 调试命令全家桶

### 8.10 实战：怎么把多条命令优化成一个 launch（本项目回放为例）

**问题**：回放原来要两条长命令——

```bash
ros2 run orcahand_teleop_ros2 hand_controller --ros-args \
  -p mock:=false -p model_path:=/home/ubuntu/.../orcahand_v1_left -p skip_joints:=pinky_abd
ros2 run orcahand_teleop_ros2 replay_targets --ros-args -p file:=...
```

**思路**：launch 能把多条 `ros2 run` 合并成一条，且把**固定参数写死**、只暴露**会变的参数**。

```python
# launch/replay.launch.py —— 关键结构
from launch import LaunchDescription
from launch.actions import DeclareLaunchArgument
from launch.substitutions import LaunchConfiguration
from launch_ros.actions import Node

def generate_launch_description():
    return LaunchDescription([
        DeclareLaunchArgument('file', description='回放CSV(必填)'),        # ① 会变的 → 声明成参数
        DeclareLaunchArgument('loop', default_value='false'),
        DeclareLaunchArgument('model_path', default_value='.../orcahand_v1_left'),  # ② 固定的 → 写死默认值
        DeclareLaunchArgument('skip_joints', default_value='pinky_abd'),

        Node(package='orcahand_teleop_ros2', executable='hand_controller',   # ③ 把原来的 ros2 run 变成 Node(...)
             name='hand_controller', output='screen',
             parameters=[{'mock': 'false', 'model_path': LaunchConfiguration('model_path'),
                          'skip_joints': LaunchConfiguration('skip_joints')}]),
        Node(package='orcahand_teleop_ros2', executable='replay_targets',
             name='replay_targets', output='screen',
             parameters=[{'file': LaunchConfiguration('file'), 'loop': LaunchConfiguration('loop')}]),
    ])
```

**做法三步**：

1. 把**每条 `ros2 run ...` 变成一个 `Node(package=..., executable=..., parameters=[...])`**
2. 会变的参数（如 `file`）用 `DeclareLaunchArgument` 声明 + `LaunchConfiguration` 引用；固定的直接写死默认值
3. 文件放包目录 `launch/`（`setup.py` 用 `glob('launch/*.py')` 自动打包），`colcon build` 后 `ros2 launch <包> <文件>.py [参数:=值]`

**进阶：可选节点用条件**（`single_pc.launch.py` 的录制选项）——

```python
from launch.conditions import IfCondition
GroupAction(condition=IfCondition(LaunchConfiguration('record')),  # record:=true 才起
            actions=[Node(..., executable='record_targets', ...)])
```

这样 `record:=true` 时多起一个录制节点，不写就不起。

> 小坑：布尔参数要用 `LaunchConfiguration`（运行时解析），直接写 `'false'` 字符串会被当字符串传给节点（`hand_controller` 会误判成 mock）——本项目踩过。
